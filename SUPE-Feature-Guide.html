03 — Step-by-Step Guide
1
Log in to Merchant Portal
Go to https://primestack-switch.onrender.com/merchant-login. Sign in with your merchant credentials.
2
Navigate to SUPE
In the left sidebar under the Merchant section, click 🔐 SUPE. The Secure Upload Processing Engine page opens.
3
Upload Your File
Drag and drop your file onto the upload zone, or click Browse to select it. Supported: SWIFT MT103, ISO 20022 XML, JSON, PDF. Max 5MB.
4
Review Extracted Fields
The engine instantly displays the parsed fields: Amount, Currency, Reference, Sender, Date, Description. Verify these match your document before proceeding.
5
Select Destination Account
Choose where the funds should be credited:
• Merchant Wallet — credits your active merchant wallet account
• Platform Reserve — credits the platform's main reserve pool
6
Add Note (optional)
Optionally add a note explaining the purpose of this upload (e.g. "Monthly wire settlement from Deutsche Bank").
7
Click "Confirm & Auto-Credit Ledger"
The system validates, posts the double-entry ledger transaction, and returns the journal reference. The credit is instant and permanent.
8
Confirm in Upload History
Click Refresh in the Upload History panel. Your upload appears with status CREDITED, journal reference, amount, and timestamp.

05 — Ledger Entry Created
// DOUBLE-ENTRY POSTED ON EVERY SUCCESSFUL UPLOAD
DEBIT  SYSTEM-FUNDING-USD         $50,000.00 USD
CREDIT  [Merchant Wallet Account]    $50,000.00 USD
Journal Ref: SUPE-A3F2D1... | Source: SUPE | File: wire-nov-2026.txt | 2026-11-20T15:00:00Z
✅
Every SUPE upload creates an immutable journal entry. The reference is permanent and cannot be modified. Duplicate references are hard-rejected — the same wire cannot be credited twice.
06 — Security & Compliance
ControlHow It Works
Duplicate preventionSHA-256 hash of merchant ID + reference — same reference always produces same journal key, rejected if already posted
Amount limitMaximum $50,000,000 per single upload — uploads above this are rejected
Admin overrideOnly SUPER_ADMIN and ADMIN roles can credit to Platform Reserve — merchants credit to their own wallet only
Audit logEvery upload creates an audit entry with user ID, merchant ID, IP address, file name, amount, and destination
Field validationAmount, currency, and reference are mandatory — empty or invalid amounts are rejected before any ledger write
No file storageFiles are parsed in-browser and never stored on the server — only the extracted fields are transmitted
07 — API Reference (Technical Integration)
ℹ
Both endpoints require a valid admin or merchant JWT in the Authorization: Bearer header.
POST /supe/process — Credit funds
// Request body
{
  "format": "SWIFT MT103",
  "amount": "50000.00",
  "currency": "USD",
  "reference": "WIRE-2026-001234",
  "sender": "Deutsche Bank AG",
  "date": "2026-11-20",
  "description": "November settlement wire",
  "destination": "merchant-wallet", // or "platform-reserve"
  "fileName": "wire-nov-2026.txt"
}
Response
{
  "journalEntryRef": "SUPE-A3F2D1E8...",
  "amount": "50000.0000",
  "currency": "USD",
  "status": "CREDITED",
  "destination": "WALLET-MERCHANT-001-USD",
  "message": "50000.0000 USD credited successfully"
}

Important: Always verify extracted fields against the original document before clicking Confirm. Once credited, a journal entry is permanent and cannot be reversed without creating a separate reversal entry through the platform admin.
